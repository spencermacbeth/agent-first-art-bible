# The save-point terminal, with its records filled in

This directory shows what the package's records look like once a pass has been through them. It follows the same fictional pass as [worked-pass.md](../worked-pass.md): a small exploration game needs a save-point terminal, and the first pass asks what its architectural identity should be.

Everything here is invented. The hashes are placeholders, the provider is called `example-provider`, the currency is unnamed, and no generation or device test is claimed. The shape of the records is the point.

```text
AGENTS.md                           the project's instruction file with the directive merged in
art-bible/
  README.md                         entry point; lists the current decision and open questions
  visual-direction.md               the terminal's entry: accepted scope, constraints, superseded direction
  references/CATALOG.md             the two seeds and one derived crop
  reviews/terminal-silhouette-01/
    task.md                         the brief that started the pass
    jobs.md                         three candidates, one reconciled after a timeout
    feedback.json                   the owner's exported notes, tied to artifact hashes
    decision-001.md                 what was accepted, at which scope, and what stays open
```

Read them in that order, or jump to the one you are about to write for your own project. Only `visual-direction.md` exists in this bible so far; the writing, sound and interface files get added when their first pass begins, which is what a real bible looks like early on.
